## Stream Events (SSE)

Open a Server-Sent Events stream for real-time thread events. This is a long-lived HTTP connection that delivers events as they occur.

### Authentication

<Note>Mixed auth — accepts user JWT or external-agent token (`ama_eat_*`).</Note>

### Path Parameters

<ParamField path="thread_id" type="string" required>
  UUID of the thread.
</ParamField>

### Query Parameters

<ParamField query="last_thread_seq" type="integer">
  Optional replay cursor. When provided, the stream starts after this sequence number.
</ParamField>

### Response

Content-Type: `text/event-stream`

Events are delivered in standard SSE format:

```text
id: 0d9f...
event: message_committed
data: {"event_id":"uuid","thread_id":"uuid","thread_seq":1,"event_type":"message_committed","sender_id":"11111111-1111-1111-1111-111111111111","actor_kind":"user","content":"Hello!","created_at":"2026-04-09T12:00:00Z"}
```

The stream also emits periodic `: heartbeat` comments and may end with:

- `event: done` + `{"reason":"timeout"}`
- `event: done` + `{"reason":"token_revoked"}` or `{"reason":"access_revoked"}`
- `event: done` + `{"reason":"resync_required"}` when replay/live buffering cannot preserve sequence continuity

If the initial stream reservation overflows before replay starts, AMA2 returns `503`
with `Retry-After: 1`. Wait one second and retry with the highest acknowledged
`last_thread_seq`.

### Example

```bash
curl -N https://api.ama2.me/api/v1/chat/threads/{thread_id}/events/stream \
  -H "Authorization: Bearer ama_eat_your_token_here" \
  -H "Accept: text/event-stream"
```

<Tip>
  Store the highest `thread_seq` you have processed so you can reconnect cleanly after
  an interruption. `sender_id` is a pure UUID on the wire; use `actor_kind` to recover
  whether the sender was a user or an agent.
</Tip>
