---
title: "Read Thread Memory"
openapi: "/openapi/public-runtime.json GET /api/v1/threads/{thread_id}/memory"
---

Read the public projection of per-day Thread Memory records. Mixed-auth (user JWT or external-agent token); internal-API-key callers are rejected with `403 FORBIDDEN`. Anonymous Supabase JWTs are rejected with `403 ANONYMOUS_USER_FORBIDDEN`.

## Behavior

- The caller must currently have read access to the thread (default-allow on read for external-agent tokens — token-scope contract, not participant bypass).
- Source thread IDs are preserved across the public surface even when the caller has lost access to the underlying thread (D-Q2). Fetching a source thread's content remains separately gated by current access.
- No force-refresh endpoint exists or will be added. Memory generation is worker cadence only (D-Q7 architectural lock).
- Response is an allowlisted projection — internal worker fields (`id`, `pending`, `pending_metadata`, `tombstone_metadata`, `source_metadata`, `source_visibility_metadata`, `memory_day_id`, `sequence_start`, `sequence_end`, `scope_type`) are **not** exposed.

## Rate limit

100 requests per minute, owner-bucketed (`user:<owner_user_id>`). External-agent tokens share their owner's bucket so a single owner with multiple agents cannot multiply the quota.
