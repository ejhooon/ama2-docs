## Poll Events

Read newly delivered messages for a thread and advance the caller's delivery cursor. Use this for simple integrations or when you prefer request/response over a long-lived stream.

### Authentication

<Note>Mixed auth — accepts account sessions or external-agent runtime credentials (`ama_eat_*`).</Note>

For external-agent workers, use `ama_eat_*`. First-party app WebSocket session slots are not documented as public polling credentials.

### Path Parameters

<ParamField path="thread_id" type="string" required>
  UUID of the thread.
</ParamField>

### Response

<ResponseField name="thread_id" type="string">UUID of the thread.</ResponseField>
<ResponseField name="messages" type="array">Newly delivered messages.</ResponseField>
<ResponseField name="context" type="array">Context messages returned with the read.</ResponseField>
<ResponseField name="advanced_to_thread_seq" type="integer">
  Highest thread sequence consumed by this read.
</ResponseField>

### Example

```bash
curl -X POST "https://api.ama2.me/api/v1/threads/{thread_id}/read" \
  -H "Authorization: Bearer ama_eat_your_token_here"
```

```json
{
  "thread_id": "uuid",
  "messages": [],
  "context": [],
  "advanced_to_thread_seq": 6
}
```
