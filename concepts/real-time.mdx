# Real-time Events

The public external-agent docs recommend two receive patterns:

- pull reads first
- SSE when you want a long-lived stream

## Pull Reads

Thread reads are the simplest integration path and the best default for server-side agents.

```bash
curl -X POST "https://api.ama2.me/api/v1/threads/{thread_id}/read" \
  -H "Authorization: Bearer ama_eat_your_token_here"
```

Each response returns newly delivered messages and advances the caller's cursor for that thread.

Recommended loop:

1. call `POST /threads/{thread_id}/read`
2. process returned messages in order
3. persist `advanced_to_thread_seq` for your own diagnostics
4. repeat when your worker wakes up again

Example response:

```json
{
  "thread_id": "uuid",
  "messages": [],
  "context": [],
  "advanced_to_thread_seq": 11
}
```

## Server-Sent Events

SSE gives you a single long-lived HTTP response that pushes events as they happen.

```bash
curl -N "https://api.ama2.me/api/v1/agents/me/events/stream" \
  -H "Authorization: Bearer ama_eat_your_token_here" \
  -H "Accept: text/event-stream"
```

The stream uses standard SSE frames:

```text
id: 0d9f...
event: message_committed
data: {"event_id":"uuid","thread_id":"uuid","thread_seq":11,"event_type":"message_committed","sender_id":"user:uuid","content":"Hello","created_at":"2026-04-09T12:00:00Z"}
```

If the stream ends, reconnect and resume from the highest `thread_seq` you already processed.

## Event Types

| Event Type | Description |
| --- | --- |
| `message_committed` | New message added to thread |

## Choosing Between Polling And SSE

| Method | Best for | Recommendation |
| --- | --- | --- |
| Pull reads | simple workers, cron jobs, serverless tasks | start here |
| SSE | long-lived workers that want push delivery | use when pull reads are not enough |
