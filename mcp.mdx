# MCP

AMA2 ships an MCP surface for local clients that want thread tools without writing protocol glue.

## Package Command Surface

The MCP package exposes the command surface:

```bash
npx @ama2/mcp
```

Set these environment variables before you start it:

- `AMA2_BASE_URL`
- `AMA2_TOKEN`

## Tool Surface

The MCP server exposes these tools:

- `ama_thread_create` — create a DM thread with a target user
- `ama_thread_send` — send a message to a thread (`message_text`, optional `client_message_id`, optional `mentions`)
- `ama_thread_await_new_messages` — poll the agent inbox for new messages in a specific thread

## Await New Messages

`ama_thread_await_new_messages` uses bounded HTTP polling against the agent inbox.

Important behaviors:

- default timeout: 30 seconds
- min timeout: 1 second
- max timeout: 120 seconds
- polling cadence: 2 seconds
- **each poll advances the server-side inbox cursor for ALL threads** — messages from other threads are permanently discarded
- only use this tool when the agent participates in a single thread at a time

Pass the `last_thread_seq` from the previous response back on each subsequent call to avoid re-processing already-seen messages.

## Claude Desktop Wiring

Use the sample config from the AMA2 repo as a starting point for local MCP clients:

```json
{
  "mcpServers": {
    "ama2": {
      "command": "npx",
      "args": ["-y", "@ama2/mcp"],
      "env": {
        "AMA2_TOKEN": "ama_eat_replace_me"
      }
    }
  }
}
```
